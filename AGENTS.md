# AGENTS.md

Tailmouse turns an iPhone into a trackpad and keyboard for a Mac. Both ends are native Swift. They exchange the same sealed datagrams over one UDP socket (USB cable, LAN via Bonjour, AWDL, tailnet) and over a Bluetooth L2CAP channel. The phone probes every route and uses the cable when it answers, otherwise the fastest live one. AWDL and the tailnet get around Wi-Fi client isolation; AWDL avoids the DERP relay detour.

## Layout and commands

- `Packages/TailmouseKit`: the protocol, with no sockets and no UI. Wire types, sealing, reliable ordering, motion totals, pairing URL, the Mac's session logic, and scroll momentum (`Momentum`: the Mac measures the release speed from arrival times and glides on a 120 Hz timer, so the phone sends nothing extra). Any logic that can be pure lives here, so `make test` covers it.
- `Mac/`: menu bar server. Network.framework listener plus CGEvent input. The main window is the SwiftUI `Settings` scene (Devices, Settings, About tabs); settings live in `UserDefaults`, the phones' keys in the Keychain.
- `iOS/`: the phone app.
- `Shared/`: sources compiled into both apps (`BLELink`).
- `DOCUMENTATION.md`: routes and the AWDL stutter, for users. Route behaviour that a user can see changes there too.
- `project.yml`: the XcodeGen spec. `Tailmouse.xcodeproj` and `iOS/Info.plist` are generated and gitignored. Change targets, Info.plist keys and settings in `project.yml`, then run `make gen`.
- `Makefile`: `test`, `mac`, `run-mac`, `install-mac`, `ios-sim`, `sim`, `ipa`, `release`. Read it for the exact `xcodebuild` lines.
- End-to-end check without a phone: `make run-mac`, then `make sim SHOT=build/shot.png`. The `sim` target writes a pairing with the Debug build's simulator key (Keychain account `sim-key`, accepted as phone `sim` by Debug builds only) straight into the simulator app's container, so no QR scan is needed. The header in the screenshot should read `LAN · n ms`, and Settings › Paths should list both LAN and Tailnet. This covers the handshake only: posting input needs Accessibility, and loopback skips the firewall, so input and the AWDL path still need a real phone.
- Driving the Mac window from a script: System Events `click` on toolbar buttons and checkboxes works. For a text field, `set value` and then `perform action "AXConfirm"`; the SwiftUI binding ignores `set value` alone. Never use `keystroke`: an `LSUIElement` app doesn't come to the front, so the keys land in whatever app does. Capture with `screencapture -l <window id>`.

## Protocol invariants

Each of these has a test in `TailmouseKitTests`. Keep the tests green when you change the protocol.

- Every datagram is sealed with ChaChaPoly under the phone's key, whatever the path. The LAN path carries keystrokes. A packet that fails to open gets no reply.
- Pointer and scroll travel as the gesture's running total (`Motion`). The Mac applies `total - lastApplied`, so loss and duplicates cost nothing.
- Clicks, keys and drag/scroll boundaries are `Event`s. Each packet carries the whole unacked window, and the Mac delivers events once, in order.
- A packet runs only under a session id that the Mac issued. First contact and stale sessions get a reply and nothing more, so replayed traffic never runs.
- Motion in a packet is applied before its events, so a click lands where the cursor is. Motion from a packet older than the newest one seen is dropped, so a slow path (DERP) can never drag the cursor back.
- An event more than `Wire.eventMaxAge` old when it reaches the Mac is consumed without running, so a click or keystroke never fires late. Releases (`dragEnd`, `scrollEnd`) always run.
- Freshness is also judged by the Mac's clock: each session tracks the smallest `now - Packet.time`, and a packet more than `eventMaxAge` behind that runs nothing and doesn't keep the session alive. Phone timestamps alone can't catch a packet an on-path attacker held back and released later.
- Motion totals must be finite and below 1e7, or the Mac's integer conversions could trap.
- When a session expires, the Mac releases held input such as an active drag.
- Each phone has its own key (`Keyring`): the key that opens a datagram is the phone's identity, sessions are kept per key, and the reply is sealed with the same key. Removing a phone deletes its key and its sessions. No shared key, no PIN, no device id on the wire.
- Pairing is one message, no handshake state. The code's `k` is an X25519 public key the Mac made for that code (private half in memory, offered only while the Pair window is open). The phone makes its own pair and derives its key at once (`Pairing.claimed`, HKDF over the shared secret, salted with both public keys). Until the Mac answers, the phone sends every datagram as a claim: `"TP" | version | phone public key | ordinary datagram` (`Seal.claim`). The Mac derives the same key from the public key in front; if the datagram opens, the sender has seen the code, the key becomes a phone and the offer is spent. A claim from a phone that already has its key opens under that key, so a lost answer costs nothing. A copy of the code gives no key; it lets someone claim first, which the user sees (the Pair window closes and the phone is in the list, their phone stays on "searching…"). The phone's key pair is made once per install (`PairingStore.identity`, kept when the pairing is forgotten), and the Mac stores the public half next to the key (64 bytes per phone in the Keychain item `phones`): a claim under a public key it has already replaces that phone's key and keeps its row. Only the holder of the private half can do that, because the claim has to open. The Debug build's `sim` phone skips all this with a ready-made key.
- The phone ignores a reply whose `echo` is older than the newest it has acted on (per path for RTT, overall for session and acks), so a replayed reply can't roll its session back.
- A `tailmouse://` link only fills `Client.pendingPairing`; nothing changes until the user confirms. Link hosts are limited to tailnet addresses and `*.ts.net` (`Route.isTailnet(host:)`), at most 8.
- The wire is a hand-written binary layout (end of `Wire.swift`, version in the `Seal` header), 46 bytes for a pointer packet against about 170 as JSON, because the Bluetooth link carries little. A field added to `Packet` or `Reply` goes at the end (behind a new flag bit in `Packet`); decoders ignore trailing bytes, so an older build still connects. Changing anything earlier needs a new `Wire.version`, which locks out older builds. The reader refuses short input, unknown event tags, and NaN or infinite numbers.
- Drawing mode is a third `Motion.Kind`, `tablet`: `x` and `y` are a position in the Mac's drawing area (0…1) and `gesture` counts strokes. The phone repeats its last motion in every packet, probes included, so `Sessions` applies a position only when it differs from the last one applied; otherwise the cursor is pulled back once a second. A new stroke number lifts the button before the jump, in case the old stroke's `dragEnd` was lost. The stroke is the existing `dragBegin`/`dragEnd`, and motion-before-events puts the press at the stroke's start. `Reply.aspect` (trailing, optional) gives the phone the area's shape.
- Pointer packets carry no identity (`name`, `via`); hellos and the 1 s probe do, and the Mac remembers it per `Packet.client`.
- New `Event` cases go at the end. v2 reserves dock, spaces, media and clipboard.

## Platform gotchas

- macOS Accessibility (TCC) permission is tied to the code signature. An ad-hoc signed build loses the permission on every rebuild. Sign with the team in `Config/Local.xcconfig`; see the `.example` file.
- `security find-identity -v -p codesigning` lists 0 valid identities while an Apple Development cert is present: the Apple WWDR G3 intermediate is missing from the login keychain.
- Paths: the phone opens one flow per tailnet host and one per Bonjour interface, each pinned with `requiredInterface`. An unpinned UDP flow to a Bonjour service settles on Wi-Fi and stays there, even when client isolation drops every packet. AWDL comes from `includePeerToPeer` on both the listener and the browser.
- The phone sends only on flows in `.ready`. An `NWConnection` that is still resolving or waiting queues every send, and cancelling one with a few thousand queued overflows the stack in Network.framework's recursive dealloc (SIGBUS in `NWConcrete_nw_write_request dealloc`). The 1 s probe fills such a queue in under an hour while another path keeps the session alive.
- USB: a plugged-in iPhone shows up on the Mac as two NCM Ethernet interfaces (`enN`, link-local only, absent from `networksetup`), and Bonjour runs on them, so the cable needs no code of its own beyond a name. The phone labels any Bonjour interface that is not Wi-Fi or AWDL "USB"; the Mac recognises the interface in the IORegistry (`isPhoneUSB`: `AppleUSBNCMData` under an Apple `IOUSBHostDevice`). `PathPicker` picks a live "USB" path over any radio, whatever the RTTs say. The simulator has no cable; `lsof -nP -a -c Tailmouse -iUDP` on the Mac shows whether a real phone has a flow on the USB interface.
- The phone rebuilds its flows (`reconnect`) on a network path update only when nothing has answered for 1.5 s. Path updates come every few seconds with a cable or AWDL around, and each rebuild stalls the pointer while Bonjour resolves. New interfaces arrive through the browser instead.
- AWDL is a last resort on the phone (`Client.awdlUp`): it browses and connects over AWDL only after nothing else answered for 2 s. A peer-to-peer browse alone makes the phone's radio leave the Wi-Fi channel for ~100 ms about twice a second (measured on a 6 GHz network), which stalls LAN and tailnet too. On the Mac three things start the same hopping, with `awdl0` active throughout: AirDrop set to Everyone (measured: about 60 of 500 pings to the gateway over 30 ms; 0 on Contacts Only or No One), the Finder's AirDrop window while open (seen as pointer stutter, not measured with ping), and our own listener with `includePeerToPeer` (about 120 of 500). So `AppModel` drops the AWDL route while the Mac is on 6 GHz unless the user overrides it (`awdlAnyway`, for 6 GHz networks with client isolation) (`Radio.on6GHz`, CoreWLAN, no location permission needed for the band) and warns when AirDrop is on Everyone (`Radio.airDropEveryone`, the `com.apple.sharingd` `DiscoverableMode` default). `sudo ifconfig awdl0 down` is not needed. Apple's sharing agents cannot be booted out without sudo (SIP). Other 5 GHz channels than 44 and 149 probably hop too; nobody measured it.
- Bluetooth: the Mac is the peripheral (`Mac/BLE.swift`), the phone the central (`iOS/BLE.swift`). The service UUID is one random id per Mac (`bleService` in the Mac's defaults, `b=` in the pairing link), the same for every phone, because a Mac cannot advertise one service per key; the PSM sits in the standard PSM characteristic, and one L2CAP channel carries the datagrams behind a length prefix (`Framer`). `BLELink` sends latest-wins, and on the phone only as fast as the Mac answers (`SendWindow`, 3 unanswered at most): the L2CAP stream accepts bytes far faster than the radio carries them, so an unclocked sender builds seconds of backlog (measured: `late` 1.8 s at 60 sends a second). iOS holds the connection interval at 30 ms whatever the Mac asks for, so the route tops out near 33 updates a second and 30 to 60 ms `late`. A phone on another wire version reconnects every 2 s and is dropped on its first frame; that loop in the `ble` log means mismatched builds. The phone keeps the link out of `reconnect`, because setting it up takes seconds. Channels follow the UDP flow rules (first frame must open, 3 s to authenticate, 4 at most). Neither the simulator nor a Mac talking to itself can exercise it: the Mac logs under category `ble`, the phone shows its state in Settings › Bluetooth.
- The drawing area (`Mac/TabletPicker.swift`) lives in CG global coordinates (top-left origin); the AppKit overlay converts once in `OverlayView.origin`. The overlay needs `ignoresMouseEvents = false` spelled out: a clear region of a transparent window otherwise lets clicks through to the window underneath. Window bounds come from `CGWindowListCopyWindowInfo` without Screen Recording permission. `Input.currentLocation` trusts its own last move for 0.25 s, because a stroke presses the button in the same packet as the jump and the system has not caught up. A scratch client on TailmouseKit over loopback can drive all of this without a phone (it moves the real cursor).
- SwiftUI: `aspectRatio(nil, contentMode: .fit)` shrinks a view to its ideal size; apply the modifier conditionally (`Shaped`).
- The Mac caps flows at 32. A flow whose first datagram fails to open is cancelled, and flows that never authenticated go after 3 s.
- `make release` (`scripts/release.sh`) signs the Mac app with Developer ID, notarizes it with `notarytool` (keychain profile `tailmouse`) and staples it. It stops early when the certificate or the profile is missing. The Apple ID and team id stay in the keychain profile and `Config/Local.xcconfig`, never in the repo.
- `make install-mac` installs a Release build: a Debug build carries `get-task-allow`, so any same-user process could attach to an app that holds Accessibility.
- The pair screen scans the code itself (`QRScanner`, VisionKit `DataScannerViewController`) and hands the text to `Client.pair(with:)`, so the confirmation stays the gate. The simulator has no camera: `isSupported` is false there and the screen shows the fallback line. To see the pair screen in the simulator, delete `Library/Application Support/pairing.json` from the app container and relaunch.
- The iOS app refuses third-party keyboards (`AppDelegate`), since everything typed goes to the Mac.
- Device names: iOS gives an app only "iPhone" (`UIDevice.current.name`, since iOS 16). The Mac looks up the host name of the address a phone sends from (`Server.lookUpName`, `Host(address:)`, off the queue, once per phone and route): the MagicDNS name on a tailnet flow, the `.local` name on the LAN. Verified for a tailnet address only. The simulator's row shows the Mac's own name, because its flows come from the Mac's address.
- Driving the Devices tab from a script: SwiftUI buttons there have no accessibility name; find them as `buttons of group of group of window "Devices"`. A table row's context menu could not be opened with `AXShowMenu`. A QR code in a `screencapture -l` image decodes with `CIDetector`.
- Route switches are enforced on the Mac: `Route.of` classifies each flow by the phone's address and a switched-off route gets no reply, so the phone's picker drops it. The Devices list shows the path the phone reports in `Packet.via` instead, because probes reach the Mac on every route.
- The iOS IPA ships unsigned (`make ipa`), and SideStore re-signs it on the phone.
- Pointer stutter: `defaults write <Mac bundle id> jitterLog -bool YES`, restart the Mac app, then `/usr/bin/log stream --predicate 'subsystem == "tailmouse"'` prints one line per route per second of traffic. `sendGap` spikes mean the phone stalled, `late` spikes with a steady `sendGap` mean the radio or network did. A stall of about 100 ms once or twice a second with a steady `sendGap` is AWDL: `ping -i 0.02` from the Mac to the gateway shows the Mac's radio hopping, to the phone the phone's.
- `Client` publishes only changed values from `received`: the Mac answers every packet, and each `@Published` write redraws the UI on the thread that handles touches.
- Raw UIKit touches with coalesced touches drive the trackpad. The screen has to stay at 120 Hz while a finger is down, because iOS delivers touches in step with the display.
- Mac input code ported from Entangle (MIT, (c) 2026 Gabriel Donadel) keeps that notice next to it.
